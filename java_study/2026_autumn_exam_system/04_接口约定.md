# 接口约定草案

状态：供第一天和前端队友对齐的设计稿。接口尚未实现，也尚未创建或写入 Apifox 项目。后续随实际代码生成 OpenAPI 文件，再导入团队 Apifox 并保存真实案例。

## 全局约定

- 本地后端拟用 `http://localhost:8080`，统一前缀 `/api`，JSON 字段用 camelCase。
- 写入请求使用 `Content-Type: application/json`。登录采用 Cookie/Session；写入请求携带 `X-CSRF-Token`。
- 日期时间格式为 `yyyy-MM-dd HH:mm:ss`，统一表示北京时间，由后端产生考试时间。
- 分页 page 从 1 开始，pageSize 默认 10，最大 50；列表返回 items、total、page、pageSize。
- HTTP 状态码表达成功/失败类别，业务 code 表达具体原因。前端不要只看 message 判断流程。
- 请求中的未知或不允许字段应被拒绝；以 DTO 白名单防止修改 role、studentId、score 等字段。

成功示例：

```json
{"code":"OK","message":"成功","data":{"score":80,"totalScore":100}}
```

失败示例：

```json
{"code":"RETAKE_REQUIRED","message":"已完成该课程考试，请通过重考开始","data":null}
```

| HTTP 状态 | 用途 |
|---|---|
| 200 | 查询、更新、提交成功；复用进行中答卷或返回已保存结果 |
| 201 | 新建题目或新建答卷 |
| 400 | JSON、字段、选项、重复题目 ID 等参数错误 |
| 401 | 未登录、会话失效或登录失败 |
| 403 | 角色、课程权限或 CSRF 校验不允许 |
| 404 | 资源不存在；学生请求不是自己的答卷时也使用此状态 |
| 409 | 当前状态不允许，例如要求重考、空题库、无历史却申请重考 |
| 500 | 非预期服务端异常，对外返回稳定错误，不返回堆栈和数据库密码 |

教师题目查询与学生答卷查询使用不同响应对象。即便两者展示题干和选项，也不把含 correctOption 的教师响应复用于学生。

## 登录和个人资料

先 GET A01 获得 `data.csrfToken`，后续写入请求放入 `X-CSRF-Token`。Apifox 同时启用 Cookie 保持；教师和学生的演示会话要隔离。

A02 登录请求：

```json
{"username":"student01","password":"<演示账号密码>"}
```

登录响应的 data：

```json
{"id":1001,"role":"STUDENT","realName":"演示学生甲","csrfToken":"<当前会话令牌>"}
```

会话标识由响应 Cookie 传递，前端按 role 选择页面。修改客户端 role 不能改变后端授权。

A04 个人资料的 data：

```json
{
  "id":1001,"role":"STUDENT","realName":"演示学生甲",
  "gender":"UNKNOWN","phone":"13800000001",
  "identityNo":"S2026001","college":"示例学院",
  "courses":[{"id":1,"name":"Java 基础"}]
}
```

gender 拟定为 UNKNOWN / MALE / FEMALE；identityNo 在学生页面标为“学号”，在教师页面标为“工号”。A05 只接收 realName、gender、phone、college，不接收 id、role、identityNo 或 courses。

## 题目增改

T04/T05 的请求体共用字段：

```json
{
  "stem":"Java 中哪个关键字用于继承类？",
  "optionA":"extends","optionB":"implements",
  "optionC":"import","optionD":"package",
  "correctOption":"A","points":10
}
```

校验规则：题干去除首尾空白后非空，最长 2000 字符；每个选项非空，最长 500 字符；correctOption 为 A/B/C/D；points 为 1–100 的整数。初版题型固定单选，不接受客户端传入其他题型。

编辑时不能通过修改 courseId 转移题目。删除题目后，旧答卷的快照仍存在。

## 学生课程与开考

S01 返回的列表项示例：

```json
{
  "courseId":1,"courseName":"Java 基础","teacherName":"演示教师甲",
  "examStatus":"COMPLETED","activeAttemptId":null,
  "latestAttemptId":101,"latestScore":80,"latestTotalScore":100
}
```

未考课程的 latest 字段为 null；重考进行中仍可保留最近一次已交卷成绩。前端根据 examStatus 展示按钮，后端独立验证请求是否允许。

S02 请求体只能为下面两种之一：

```json
{"mode":"FIRST"}
```

```json
{"mode":"RETAKE"}
```

新建成功返回 201，复用现有进行中答卷返回 200。data 示例：

```json
{"attemptId":102,"attemptNo":2,"status":"IN_PROGRESS","reused":false}
```

S03 进行中答卷的 data 示例：

```json
{
  "attemptId":102,"courseId":1,"courseName":"Java 基础",
  "attemptNo":2,"status":"IN_PROGRESS","totalScore":100,
  "items":[
    {"itemId":501,"positionNo":1,"stem":"Java 中哪个关键字用于继承类？",
     "optionA":"extends","optionB":"implements","optionC":"import","optionD":"package","points":10}
  ]
}
```

示例只展示一题；totalScore 以实际整卷为准。itemId 是“本次答卷的题目明细 ID”，不是当前题库 questionId。

## 交卷与结果

S04 请求示例：

```json
{"answers":[{"itemId":501,"selectedOption":"A"},{"itemId":502,"selectedOption":"C"}]}
```

不传 score、correctOption、studentId。未回答的题可省略；空 answers 数组代表全部未答。重复 itemId、属于其他卷的 itemId 或 A–D 以外的选项返回 400，整张卷仍保持未交卷状态。

S04/S05 的结果 data：

```json
{
  "attemptId":102,"attemptNo":2,"status":"SUBMITTED",
  "courseId":1,"courseName":"Java 基础",
  "score":80,"totalScore":100,
  "startedAt":"2026-09-07 14:00:00","submittedAt":"2026-09-07 14:15:00"
}
```

同一 attemptId 已交卷后再提交，不重新判分，即使第二次答案不同也返回第一次已保存结果；需要重新作答必须创建重考答卷。

## 成绩列表

T07 每位已交卷学生返回最近一次成绩；字段包括 studentId、studentName、identityNo、courseId、courseName、attemptId、attemptNo、score、totalScore、submittedAt。点击学生时调用 T08 展示全部已交卷历史。

T08/S06 按 attemptNo 倒序；所有列表查询都先应用权限条件，再做分页。不能分页后才过滤他人的数据。
