# 接口交付

- `openapi.json`：从应用实际接口导出的 OpenAPI 3 文档，可导入 Apifox。
- `examples/`：自动化测试生成的成功、失败、异常响应记录，标注了测试所用数据库和调用方式；不包含会话 Cookie。
- `verification-http.json`：实际 HTTP 冒烟测试的摘要（执行成功后生成）。

## Apifox 使用

1. 在 Apifox 创建团队项目，选择“导入数据 → OpenAPI/Swagger”，导入本目录的 `openapi.json`。
2. 设置环境地址为实际后端地址（默认 `http://127.0.0.1:3636`），启用 Cookie 保持。教师、学生分别使用隔离的 Cookie 会话。OpenAPI 的 `servers.url` 现在是 `/`，在线调试会跟随文档主机和端口；离线导入仍需明确填写环境地址。
3. 调用 `GET /api/auth/csrf`，保存 `data.csrfToken`。
4. 登录请求添加 `X-CSRF-Token` 请求头；登录成功后，用响应中的新令牌替换旧令牌。后续写请求都携带它。
5. 按 [接口约定](../04_接口约定.md) 中的案例逐项运行，在团队 Apifox 中保存请求与实际响应。
6. 交卷所用 `itemId` 必须来自本次获取的答卷，不要把示例记录中的历史 ID 直接当作当前数据库 ID。

这些本地文件不等于已经在 Apifox 上保存案例；团队项目导入、案例保存和前端联调仍需实际完成。

## 本地 HTTP 验证

在未修改题库的演示数据库上启动后端，再从项目目录执行：

```powershell
.\scripts\smoke.ps1
```

脚本会用公开演示账号完成登录、开考、交卷、重复提交、重考、教师查分、越权拒绝和退出失效验证。它会新增真实考试记录，不用于生产数据库。

## 更新接口定义

运行后端后，可将实际后端地址下 `/v3/api-docs` 的响应另存为 `openapi.json`。修改接口时同步更新定义、案例和联调记录。
