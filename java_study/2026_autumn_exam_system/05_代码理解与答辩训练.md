# 代码理解与答辩训练

本文件对应未来的在线考试系统实现。当前没有可引用的本项目 Java 行号，文中类名是计划定位点。生成每批代码后，要补充实际文件路径、断点与运行结果，再用这些证据准备答辩。

## 每个文件都要回答的六个问题

1. 谁调用它？入口是哪个 HTTP 请求，还是另一个 Java 方法？
2. 输入是什么？哪些字段来自用户，哪些来自 Session 或数据库？
3. 它处理什么规则？如果删除这段检查，具体会错在哪里？
4. 它依赖谁？构造器中的对象由 Spring 怎样提供？
5. 结果是什么？改了哪些表，返回哪些字段？
6. 怎样证明正确？成功、失败、异常各用什么请求或测试验证？

注释优先解释“为什么这样写”，例如为何锁答卷、为何用题目快照。对于 Java 语法本身，你已学过的部分直接用自己的话讲。

## 三条必须会追踪的调用链

| 业务 | 计划阅读顺序 | 最容易被问的地方 |
|---|---|---|
| 查询课程 | Controller → Course/Grade Service → Mapper → XML SELECT → 课程响应 | 身份从哪来？SQL 怎么过滤学生的选课？空列表怎么办？ |
| 新增题目 | 请求 DTO → `@Valid` → Controller → QuestionService → Mapper INSERT | 谁检查这门课属于教师？正确答案为什么不返回学生？ |
| 提交试卷 | SubmitRequest → ExamController → ExamService 事务 → 锁答卷 → 判分 → 更新明细和成绩 | 重复请求、回滚、正确答案来源、快照、重考与原成绩 |

读码顺序建议从一次请求出发，不按文件夹名称从头读到尾。阅读交卷逻辑时，把数据库里同一 attemptId 的答卷和明细放在旁边看。

## 核心问答：用自己的项目举例

**1. Spring、Spring MVC、Spring Boot 分别做什么？**

Spring 管理对象和依赖，并提供事务等能力；Spring MVC 把 HTTP 请求映射到 Controller、把请求数据转为 Java 参数、把响应对象转为 JSON；Boot 根据依赖和配置帮助组装、启动应用。我们的 SQL 仍由 MyBatis 执行，业务仍由 Service 编写。

**2. IoC 和 DI 是什么？**

本来需要自己创建 QuestionService、QuestionMapper 并连接它们；使用 Spring 后由容器组织对象，QuestionService 通过构造器接收 Mapper。IoC 描述控制权交给容器，DI 描述依赖如何提供进来。能指出自己类里的构造器比背定义更有用。

**3. Controller 为什么不直接写全部判分和 SQL？**

Controller 处理 HTTP 输入输出；判分、归属和事务由 Service 统一组织；SQL 放 Mapper。这样同一业务规则有明确位置，也更容易独立测试。分层的价值要能通过一次修改展示出来。

**4. `@RequestBody`、`@RequestParam`、`@PathVariable` 有什么区别？**

交卷 JSON 用 `@RequestBody`；page、pageSize 这样的查询字符串用 `@RequestParam`；路径里的 attemptId 用 `@PathVariable`。请求位置与注解不匹配时，常出现参数为空或 400。

**5. MyBatis 的 Mapper 为什么只有接口也能调用？**

MyBatis 为接口建立代理，将方法映射到配置的 SQL，再执行参数绑定和结果映射。需要核对 XML 的 namespace、语句 id、参数名与 Java 方法，而不是寻找一个手写的 MapperImpl。

**6. `#{}` 和 `${}` 有什么区别？**

`#{}` 用于参数绑定，用户输入作为值处理；`${}` 是文本替换，直接接受用户输入会产生 SQL 注入风险。动态排序用后端白名单选择固定 SQL 片段，不能把客户端排序表达式直接拼进去。

**7. 为什么题目接口不用同一个实体对象全部返回？**

数据库对象包含 correctOption、密码等后端字段；学生只需要题干、选项和分值。用独立响应 DTO 明确允许输出的字段，避免新增字段后意外泄露。请求 DTO 同样限制学生可以提交哪些字段。

**8. Cookie 和 Session 分别存在哪里？**

Cookie 保存在客户端，携带会话标识；Session 在服务端保存登录状态。请求再次携带标识时，服务端据此识别用户。前端传一个 studentId 并不能证明它就是这个学生。

**9. 为什么前端隐藏教师按钮还不够？**

任何人都可以直接发 HTTP 请求。后端既要检查 role 为 TEACHER，也要检查目标课程确实属于当前教师。仅检查教师角色不能阻止教师修改其他人的课程。

**10. Spring Boot 自动配置是不是自动生成代码？**

自动配置依据类路径和属性配置 Bean，例如 Web 依赖触发相应 Web 配置。它不替我们决定考试规则，也不自动生成考试业务代码。能指向 pom.xml 和 application.yml 说明哪些依赖/属性起作用即可。

**11. 为什么本项目用 Boot 2.7？**

用户指定 JDK 8，因此选择官方兼容的 Boot 2.7.18 和 MyBatis Starter 2.3 系列。依赖要按兼容组合选，不能直接复制需要更高 JDK 或使用 jakarta 包名的新教程。

**12. 判分为什么必须在后端？**

浏览器数据可以被修改。前端只提交“哪道答卷题选了哪个选项”；后端从自己的快照中取正确答案和分值计算。客户端传 score 或 correctOption 应被拒绝。

**13. 重考为什么不能覆盖原来的成绩？**

考核要求能查看每次考试。每次开考建立新的 exam_attempt，attemptNo 增加，题目和成绩明细属于各自的答卷。更新同一条总成绩会丢失历史。

**14. 教师改题之后，旧试卷按哪个答案判分？**

按开考时复制的快照。当前题库用于创建未来的答卷，已有答卷使用自己的题目、标准答案和分值。这使考试期间改题不会改变已开始的考试。

**15. `@Transactional` 解决什么问题？**

交卷需要同时更新各题得分、总分和状态。如果中间失败，只保存了一半就会产生不一致。事务要求这些写入共同成功或回滚。实际演示应在独立测试库中模拟中途异常，查看多张表的结果。

**16. 事务为什么可能不生效？**

常见原因包括对象未被 Spring 管理、调用没有经过代理、同类内部直接调用、异常被吞掉或回滚规则不覆盖该异常。根据自己代码的调用路径和测试回答，不能只说“加了注解”。

**17. 两次同时交卷怎么处理？**

事务内锁定同一答卷行。第一个请求完成判分后将状态更新为 SUBMITTED；后来的请求读到已提交状态，返回保存结果。前端禁用按钮只是改善体验，后端仍要处理网络重试和并发。

**18. 两次同时点开考呢？**

先锁同一学生同一课程的选课行，再检查是否存在进行中的答卷并创建。这样不同请求不能同时通过“还没有答卷”的判断。对同一进行中答卷反复开始会复用已有 ID。

**19. Apifox 能调用，浏览器为什么不能？**

浏览器有同源和 Cookie 发送规则；需要检查请求 URL、前端代理、Cookie、预检响应和 CSRF Token。Apifox 不完全复现浏览器限制，必须看浏览器真实请求做联调。

**20. 你怎么排查接口返回 500？**

先保存可复现请求；从日志找到第一条有业务含义的异常；确认请求是否到达 Controller、DTO 是否正确、Service 判断是否合理、SQL 是否执行、数据库结果是否符合预期。不要连续随机修改多个文件。

**21. 为什么数据库有外键/唯一约束还要业务校验？**

外键能保证关联存在，不能保证关联的用户角色正确或课程属于当前用户。唯一约束阻止重复数据，Service 校验负责清楚表达业务并返回合适错误。两者共同保障正确性。

**22. Git 的 commit 和 push 有什么区别？**

commit 将变化记录为本地版本，push 把本地提交同步到远程。团队通过功能分支隔离开发并合并检查；公开仓库便于组长拉取。本仓库当前记录的是规划，业务代码后续按实际开发批次提交。

**23. Mock.js 能证明后端完成了吗？**

模拟数据帮助前端先开发页面；它没有证明 Java 判分、MySQL 保存和权限检查正确。最终用真实后端请求及数据库证据验收；没有前端时按通知把真实接口全部跑通。

**24. AI 在项目中做了什么，你做了什么？**

根据实际情况回答：AI 协助哪批代码、哪些方案比较；自己如何核对需求、检查 SQL、设计失败场景、排错和修改。准备一个真实案例，例如发现成绩被前端控制或重考覆盖历史，并展示修正及验证证据。没有实际做过的修正不要写入答辩经历。

## 现场改码练习

| 难度 | 题目 | 验证要求 |
|---|---|---|
| 基础 | 题干最多 2000 字改为 1000 字 | 1000 字通过，1001 字返回字段错误 |
| 基础 | 学生资料增加一个已有数据库字段的展示 | GET 响应正确，未意外开放身份字段更新 |
| 中等 | 教师成绩列表增加学号筛选 | 有匹配、无匹配、空条件各测一次 |
| 中等 | 历史按考试时间倒序，时间相同时按 ID 倒序 | 相同时间的顺序仍稳定 |
| 中等 | 把课程列表“最近成绩”改成“最高成绩” | 解释 SQL、字段命名、前端文案和测试如何一同改变 |
| 进阶 | 增加最多三次考试规则 | 第三次可创建，第四次拒绝；复用进行中答卷不算新次数 |

训练时不要同时做全部进阶题。先完成基础功能，再选两道能独立改动的题。

## 模拟答辩流程

前 2 分钟：说明需求、角色、技术栈、六张表和自己的职责。

随后 4 分钟：教师新增题目 → 学生答题交卷 → 展示成绩 → 重考 → 教师查看两次历史。

随后 3 分钟：重复交卷结果不变；教师改题后旧卷使用快照；展示对应代码与测试证据。

最后 1 分钟：如实介绍 AI 协助方式、自己负责的验证和一个已知可优化点。

再安排 20 分钟随机追问和 20 分钟现场修改。两次模拟间只针对答不上来的点补课。

## 完成一次模块学习的标准

能够不用提示讲完整条调用链；能定位和解释关键注解；能手写核心判断的伪代码；能独立完成一个小改动；能用成功和失败请求验证。只有“代码看着眼熟”时，在记录表中标为待练习。
